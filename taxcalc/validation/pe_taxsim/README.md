Validation against PolicyEngine-US using PolicyEngine-TAXSIM tool
=================================================================

This folder compares Tax-Calculator's **federal** income and payroll
tax results with those of
[policyengine-taxsim](https://github.com/PolicyEngine/policyengine-taxsim)
for random samples of filing units in each year 2021 through 2025.
By focusing on years beginning in 2021, the PolicyEngine-TAXSIM tool
returns tax amounts generated by PolicyEngine-US (not TAXSIM).
Each validation sample is identified by an assumption-set letter `L`
(`a`, `b`, or `c`) and a two-digit year `YY`.
The comparison involves five steps:

1. [`../common/generate_sample.py`](../common/generate_sample.py),
   which is shared with other validation workflows, writes a
   TAXSIM-format sample `samples/LYY.in.csv.gz`
   (always `state=0`, `idtl=2`) containing joint (40%), head of
   household (30%), single (15%), and married filing separately (15%)
   filing units.  Its required `--workflow` option names the
   validation workflow that uses the sample (`pe_taxsim` here), which
   sets the default output folder (`validation/WORKFLOW/samples`) and
   the default maximum number of dependents (5 for `pe_taxsim`; 3 for
   the planned `tbly_ts` workflow, because Tax-Simulator records only
   three dependent ages).  Its `--max-depx M` option (M in 3-5)
   changes the maximum number of dependents and, when M differs from
   the workflow default, requires `--outdir`, so the committed samples
   are never overwritten.  Its `--all` option, used in place of the
   `LETTER` and `YEAR` arguments, writes all fifteen samples.
2. `run_pe.py` runs policyengine-taxsim on the sample and writes
   `pe_output/LYY.out-pe.csv.gz` plus a version stamp
   `pe_output/LYY.out-pe.stamp.json`.
3. `taxsim_to_tc.py` translates the sample into a Tax-Calculator input file.
4. `run_tc.py` runs the Tax-Calculator CLI with the `pe_emulation.json`
   reform and converts its output to TAXSIM format.
5. `compare.py` compares the two outputs, writes the differences to
   the `work/differences/` folder, and prints a summary of them.

The samples and PE outputs are committed, so steps 3-5 can be rerun
using only the `taxcalc-dev` conda environment.  Generated working
files are written to the git-ignored `work/` folder.

Other files in this folder: [`VARIABLES.md`](VARIABLES.md) documents
how each TAXSIM input and output variable corresponds to
Tax-Calculator variables; [`pe_pin.json`](pe_pin.json) pins the PE
version; [`pe_emulation.json`](pe_emulation.json) is the
Tax-Calculator reform that adopts PE's conventions; and `dumpvars.txt`
lists the Tax-Calculator variables that step 4 writes.

Rerunning the comparison
------------------------

From the top-level repository folder, in the `taxcalc-dev` conda
environment, run:

```
python taxcalc/validation/pe_taxsim/validate.py
```

This runs steps 3-5 for all fifteen samples (letters `a`, `b`, `c`
times years 2021-2025) in about one minute and prints a summary of the
differences for each sample.  Neither uv nor PolicyEngine is needed.
The `test.sh` script (run by `make valtest`) runs `validate.py` and
checks that its output is the same as the committed
`test_results.expect` file.  A difference means that a Tax-Calculator
change altered at least one compared result: examine the
`work/differences/LYY-taxdiffs.csv` file for each sample
whose summary changed and decide whether the change fixes a bug (then
regenerate `test_results.expect`) or whether the Tax-Calculator change
introduces a bug.  See [Running all the steps](#running-all-the-steps)
for options.

Results summary
---------------

Output generated by `validate.py` includes the pinned PE version
information and results for 10,000 random filing units in each sample.
The three sample ASSUMPTION SETS generate increasingly complex tax units:

- `a`: wages, ages of head and spouse, and up to five dependents;
- `b` ADDS TO `a`: pensions, Social Security benefits, dividends, interest,
  capital gains and losses, unemployment compensation, rental income,
  and self-employment, business, and S-corporation income (each of
  the last three nonzero in only 25% of units);
- `c` ADDS TO `b`: property taxes, mortgage interest, other itemized
  deductions, and child care expenses (for tax units with at least one
  dependent under age 13).

Twenty-three TAXSIM output variables are compared (see
[`VARIABLES.md`](VARIABLES.md)).  All of them agree to within $1
except for those summarized in the `test_results.expect` file.

The `pe_emulation.json` entries assume full take-up of the EITC and
the refundable child tax credit, as PE does, and that every married
filing separately unit lived with the spouse, as PE does when
computing taxable Social Security benefits.

The [`SUMMARY.md`](SUMMARY.md) file contains a high-level summary of
the current validation results.

Validation of a new tax year
----------------------------

To add a year, change `LAST_YEAR` in the five scripts in this folder
that define it and in `../common/generate_sample.py`, check the
year-specific logic in `run_tc.py` and [`VARIABLES.md`](VARIABLES.md)
for the new year's law changes, generate the samples and PE outputs
for the new year (steps 1 and 2), and examine every difference the
way the existing ones were examined before regenerating
`test_results.expect`.  To move to a newer PE version, update `pe_pin.json` (see
[Updating the PE pin](#updating-the-pe-pin)), regenerate all fifteen
PE outputs with `python run_pe.py --all --force`, and re-examine every difference;
the samples need not change.

Environment setup
-----------------

Steps 1, 3, 4, and 5 run in the `taxcalc-dev` conda environment from
the top-level repository folder, so the working-tree Tax-Calculator
code is the code being validated.

Step 2 runs policyengine-taxsim in an ephemeral environment managed
by [uv](https://docs.astral.sh/uv/); no PolicyEngine package is ever
installed in `taxcalc-dev`.  Install uv with the Astral installer,
which puts `uv` and `uvx` in `~/.local/bin`:

```
curl -LsSf https://astral.sh/uv/install.sh | env INSTALLER_NO_MODIFY_PATH=1 sh
```

and update it later with `uv self update`.

The policyengine-taxsim commit, the `policyengine-us` and
`policyengine-core` versions, the Python version, and the extra
policyengine-taxsim options are pinned in [`pe_pin.json`](pe_pin.json).
Step 2 is equivalent to this command:

```
uvx --python 3.13 \
    --from git+https://github.com/PolicyEngine/policyengine-taxsim@c0d565948af3896e3a6e4d34970f7502d17cdf34 \
    --with policyengine-us==2.87.0 \
    --with policyengine-core==3.33.14 \
    policyengine-taxsim policyengine LYY.in.csv --output LYY.out-pe.csv \
    --scorp-treatment active
```

`python run_pe.py L YYYY` builds and runs this command from
`pe_pin.json`, first checking that the uv environment resolves to the
pinned `policyengine-taxsim`, `policyengine-us`, `policyengine-core`,
and Python versions.  It refuses to overwrite an existing PE output
unless `--force` is given, and it checks that the output has the
expected columns and the same `taxsimid` and `year` values as the
input sample.  A 10,000-unit run takes about fifteen seconds.
`python run_pe.py --all` runs all fifteen samples, using five
concurrent processes unless `--jobs N` specifies a different number;
it resolves the pinned uv environment once before starting the
concurrent runs, reports any run that fails, and takes a little over
one minute with the default five processes.

The `--with policyengine-us==...` option is required, because
policyengine-taxsim does not set an upper bound on its
`policyengine-us` dependency, and the `--with policyengine-core==...`
option is required, because `policyengine-us` does not set an upper
bound on its `policyengine-core` dependency.  Change the pin only
deliberately, because doing so requires regenerating all the committed
PE outputs and re-examining all the differences.

Updating the PE pin
-------------------

`python update_pe_pin.py` finds the newest commit on the
policyengine-taxsim default branch (using the GitHub API) and the
newest `policyengine-us` release (using the PyPI API), resolves that
candidate pin with uvx to get the `policyengine-taxsim`,
`policyengine-core`, and Python versions actually used, and lists each
`pe_pin.json` entry that would change.  It is a dry run unless
`--write` is given, and it never writes a pin that uvx cannot resolve.
Use `--sha SHA` to pin a specific policyengine-taxsim commit instead
of the newest one, and `--python X.Y` to change the pinned Python
version.  The `pe_cli_options` entry is never changed.  After writing
a new pin, regenerate all the PE outputs (`python run_pe.py --all --force`),
re-examine every difference, and update the PE versions mentioned in
this file (such as in the uvx command above) and in
[`SUMMARY.md`](SUMMARY.md).

A new PE version often removes some of the differences and may add
new ones.  Run `validate.py`, examine every new or changed difference
in `work/differences/`, and then regenerate
`test_results.expect`.

Regenerating everything
-----------------------

This command sequence updates the PE pin, regenerates all fifteen
samples and PE outputs, regenerates all the Tax-Calculator outputs,
and compares the results with the committed `test_results.expect`.
Run these from `taxcalc/validation/pe_taxsim`, in the `taxcalc-dev`
conda environment, with uv/uvx installed:

```
cd taxcalc/validation/pe_taxsim

# 1. update the PE pin: dry run first to see what would change, then write it
python update_pe_pin.py
python update_pe_pin.py --write

# 2. regenerate all 15 samples into samples/
python ../common/generate_sample.py --all --workflow pe_taxsim

# 3. regenerate all 15 PE outputs into pe_output/ (--force allows overwriting)
python run_pe.py --all --force

# 4+5. regenerate the TC outputs in work/ and run the comparisons
python validate.py > test_results.actual

# see what changed relative to the committed results
diff test_results.actual test_results.expect
```

Note that the "4+5" command is equivalent to executing "make valtest" in
the top-level folder of the repository.

Step 3
------

`python taxsim_to_tc.py L YYYY` translates `samples/LYY.in.csv.gz`
into the Tax-Calculator CLI input file `work/LYY.in-tc.csv`, following
the input tables in [`VARIABLES.md`](VARIABLES.md).  It stops if a
TAXSIM input that has no translation (`nonprop`, `transfers`,
`rentpaid`, `pprofinc`, `sprofinc`) is nonzero, and it checks that
every output column is a Tax-Calculator input variable, that `MARS`
and `XTOT` agree with `mstat` and `depx`, that the wage and
self-employment totals equal the sums of their spouse parts, and that
the dependent counts are nested by age.

Step 4
------

`python run_tc.py L YYYY` runs the Tax-Calculator CLI on
`work/LYY.in-tc.csv`, which is equivalent to this command run in the
`work/` folder with the top-level repository folder on `PYTHONPATH`:

```
python -m taxcalc.cli.tc LYY.in-tc.csv 20YY --reform ../pe_emulation.json \
    --dumpdb --dumpvars ../dumpvars.txt --exact --silent
```

The `--exact` option makes Tax-Calculator round phase-out excesses
the way the statute and tax forms do (for example, the child tax
credit falls by $50 for each $1,000 "or fraction thereof" of income
above the threshold), as PE does; without it, Tax-Calculator phases
credits out smoothly, which differs from PE in 2021, whose $112,500
head-of-household threshold is not a multiple of $1,000.

It renames the CLI's SQLite output to `work/LYY.dumpdb` and converts
the `reform` table (current law plus `pe_emulation.json`) into the
TAXSIM-format file `work/LYY.out-tc.csv`, following the output table in
[`VARIABLES.md`](VARIABLES.md).  A 10,000-unit run takes about four
seconds.

Because the input file is neither `cps.csv` nor `tmd.csv`, the CLI
reads it with `Records(start_year=TAXYEAR, gfactors=None,
weights=None)`: the input values are used unchanged for TAXYEAR (no
growfactor aging), `FLPDYR` is set to TAXYEAR, and all weights are
zero, which matters only for the `--tables` and `--graphs` output that
step 4 does not use.

Step 5
------

`python compare.py L YYYY [--tolerance T]` compares
`pe_output/LYY.out-pe.csv.gz` with `work/LYY.out-tc.csv` for the
variables marked "Compare" in the output table in
[`VARIABLES.md`](VARIABLES.md) (`v13`, `v17`, and `v19` only for the
units described there).  It writes two files to
`work/differences/` and prints the summary rows for the
variables that have differences:

- `LYY-taxdiffs.csv` has one row (`taxsimid`, `variable`, `pe`,
  `tc`, `diff`) for each compared value whose absolute difference,
  `diff = tc - pe`, exceeds the tolerance (default $1).
- `LYY-taxdiffs-summary.csv` has, for each compared variable, the
  number of units compared, the number of differences, and the
  maximum and mean absolute difference.

The exit code is 0 on success and 2 on error.

Running all the steps
---------------------

`python validate.py` runs steps 3-5 for every letter and year using
the committed samples and PE outputs and prints each comparison; its
exit code is 0 only when every step runs without error.  All fifteen
comparisons take about one minute.
Use `--letters` (e.g., `ab`) and `--years` (e.g., `2021,2023-2025`) to
run a subset, and `--tolerance` to change the tolerance.

With `--regen`, `validate.py` first runs steps 1 and 2
(`../common/generate_sample.py` and `run_pe.py --force`), which **overwrites**
the samples and PE outputs.  Do that in the committed folders only
deliberately.  `--datadir DIR` makes `validate.py` use the
`samples`, `pe_output`, and `work` folders in `DIR` instead of those next to the scripts, so a quick trial run with
a small sample leaves the committed files alone:

```
python validate.py --letters a --years 2021 --regen --size 100 \
    --datadir /some/scratch/folder
```
