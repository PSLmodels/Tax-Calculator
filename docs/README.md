# Tax-Calculator documentation README

The files in this folder are the source for the Tax-Calculator
documentation website at <https://taxcalc.pslmodels.org>.  This README
is not part of the website (`myst.yml` excludes all `README.md`
files); it explains how the website is built.

## How the website is built

The website is built by [Jupyter Book 2](https://jupyterbook.org),
which uses the [MyST](https://mystmd.org) document engine.  The
`myst.yml` file contains the website configuration and its table of
contents.  Jupyter Book 2 is installed as part of the `taxcalc-dev`
conda environment specified in the top-level `environment.yml` file,
and it requires that [Node.js](https://nodejs.org) version 18 or
later be installed on your computer.

## Generated files

**Do not edit the following files**, which are generated by the
`make docs` command executed in the top-level Tax-Calculator folder:

* `guide/assumption_params.md`, `guide/input_vars.md`,
  `guide/output_vars.md`, and `guide/policy_params.md`, which are
  generated by `guide/make/make_uguide.py` (see `guide/README.md`)

* `api/*.md`, which are generated by `api/make/make_api.py` from the
  docstrings in the `taxcalc` package source code

## Working on the documentation locally

Execute these commands in the top-level Tax-Calculator folder:

* `make docs-peek` starts a local server that displays the website at
  <http://localhost:3000> and updates the display each time you save
  an edited file.  Press Ctrl-C to stop the server.  This is the
  quickest way to see how your edits look.  It does not execute the
  recipe notebooks or regenerate the files listed above, so run
  `make docs` first if you have changed a JSON file or a docstring.

* `make docs-html` regenerates the files listed above and then builds
  the complete website in the `_build/html` folder using the same
  commands as the GitHub CI workflows.  The build executes the recipe
  notebooks and fails on any warning, so if this command succeeds, the
  CI documentation check should also pass.  To browse the built
  website, execute:
  ```
  python -m http.server 8000 -d docs/_build/html
  ```
  and then visit <http://localhost:8000>.  (Opening the HTML files
  directly in a browser does not work because the website's links are
  relative to the website's root.)  Press Ctrl-C to stop the server.

The `_build` folder is ignored by Git.

## Redirect pages

Jupyter Book 2 page URLs differ from those produced by earlier
versions (for example, `guide/policy_params.html` is now
`guide/policy-params`).  After the website is built, the
`make_redirects.py` script writes a redirect page at each old URL so
that existing links to the website continue to work.  The script fails
if a file in the `myst.yml` table of contents has no website page.

Each redirect page points to the new URL with a trailing slash (for
example, `/usage/data/`).  This is necessary because GitHub Pages
responds to a `/usage/data` request by serving the `usage/data.html`
redirect page (rather than the `usage/data/index.html` website page),
so a redirect to `/usage/data` would loop forever.

## GitHub CI workflows

Three workflows in the `.github/workflows` folder build the website:

* `check_jupyterbook.yml` builds the website (failing on any warning)
  on every push and pull request, but does not deploy it.

* `deploy_jupyterbook.yml` builds the website and deploys it to the
  `gh-pages` branch, from which it is served, whenever a commit is
  pushed to the `master` branch.

* `deploy_parameters_docs.yml` does the same whenever a new release is
  published.
